# upstream v0.7.16 合并设计

## 目标

将 `upstream/v0.7.16` 合并到当前分支，在保留 upstream 后续架构、缺陷修复和性能优化的前提下，重新移植仍有独立价值的本地功能。合并不得覆盖未跟踪文件，不运行 `next build`。

## 已评估方案

### 方案一：逐个冲突块选择 ours/theirs

优点是操作直观；缺点是同一冲突块经常同时包含本地早期实现和 upstream 后续重构，容易无意回退 IME、扩展 UI、移动端、会话恢复、文件安全与性能修复，因此不采用。

### 方案二：以 upstream 为主体，重新移植本地独有能力

先保留 upstream 的文件结构和依赖集合，删除被 upstream 替代的本地实现，再以小范围补丁移植独有能力。冲突处理清晰，可按功能验证，采用此方案。

### 方案三：放弃本地提交后逐个 cherry-pick

可以获得干净历史，但本地 11 个提交多为混合提交，单个提交同时包含应保留和应放弃的内容，仍需要大量拆分，且比一次 merge 更难保留分支关系，因此不采用。

## 合并原则

1. `ChatInput`、`ChatWindow`、`FileExplorer`、`FileViewer`、`ModelsConfig`、`SkillsConfig`、`useAgentSession` 和 `rpc-manager` 以 upstream 实现为基础。
2. `AppShell`、`MessageView`、`SessionSidebar`、文件 API 和默认工作区策略进行人工融合。
3. `package.json` 使用 upstream 的版本和依赖集合；`package-lock.json` 与 `bun.lock` 按最终清单重新生成或采用 upstream 一致版本，禁止逐块手工拼接。
4. 删除已被替代的本地 Mention、Mermaid、MarkdownViewer、SlashCommand 和旧数学归一化实现，以及对应孤儿类型。
5. 不保留将整个 home 目录加入共享文件 allow-list 的行为。

## 保留的本地能力

### Assistant 结束状态

保留 `getAssistantStatusText()` 及其测试，在 upstream 的 `MessageView` 中显示没有对应工具调用结果的 `error` 和 `aborted` 状态。不得替换 upstream 的 Markdown、compaction、diff、extension message、deferred thinking 和 memo 逻辑。

### 默认工作区路径

继续使用 `~/.pi/default-workspace/YYYYMMDD`。除 `default-cwd` 外，同步更新 `lib/file-access.ts` 的持久扫描规则和 AGENTS.md 说明，使服务重启后仍能识别该目录。

### 发送快捷键

保留 `useSendShortcut` 的 `enter-send` 与 `mod-enter-send` 配置，在 upstream 的键盘处理顺序中接入。IME、斜杠菜单、文件补全、消息队列和 Escape 中止逻辑必须保持优先。

### 统一设置入口

保留单一设置入口的产品意图，但基于 upstream 的 Models、Skills 和 Plugins 能力重新接线。不得用旧 embedded 实现覆盖 OAuth、Skill 更新/安装和移动端适配。若一次合并无法以小改动安全实现，则保留三个 upstream 弹窗，并把统一外壳留作后续独立变更。

### 外部编辑器和文件管理器动作

仅在能复用 upstream `file-access` 校验且不会阻塞请求时移植。自定义编辑器路径、Nova、终端编辑器及远程部署语义必须明确；若无法在本次合并内可靠处理，则暂不移植旧实现。

## 清理范围

以下旧实现若不再被引用则删除：

- `components/MentionPopup.tsx`
- `components/MermaidBlock.tsx`
- `components/MarkdownViewer.tsx`
- `components/SlashCommandPopup.tsx`
- `hooks/useFileMention.ts`
- `hooks/useFileMentionCaret.ts`
- `lib/normalize-math.ts`
- 仅服务于旧实现的测试数据、类型和 RPC export 分支

旧的文件提及设计/计划文档与最终实现不一致时删除或明确标记为历史资料。

## 验证

1. 运行所有 `*.test.mjs`。
2. 运行 `node_modules/.bin/tsc --noEmit`；若 `.next/dev/types` 陈旧，先通过非破坏方式隔离缓存后重新验证。
3. 运行 `npm run lint`，不使用已失效的 `next lint`。
4. 不运行 `next build`。
5. 重点检查 assistant error/aborted、Enter/Cmd/Ctrl+Enter、IME、斜杠、`@` 文件补全、文件预览与上传、默认工作区访问、Models/Skills/Plugins 入口。

## 完成标准

- merge 提交可创建，仓库不存在冲突标记。
- upstream v0.7.16 的依赖和主要能力未被本地旧实现回退。
- 已选择保留的本地能力通过测试或明确记录为暂缓项。
- 合并前存在的未跟踪文件保持未跟踪且内容未被修改。
